The earlier signed `af9ce7b` candidate crashed three times when an accessibility press selected a destination after saved-profile relaunch. Matching macOS crash reports and QtWidgets symbols place the fault in `QAccessibleTableCell::selectCell()` calling `QAbstractItemView::selectionModel()`. The output menu now uses the app's existing independently owned accessible rows, also used by the audio-source menu. This avoids the generic Qt table-cell selection path; Windows receives no runtime change. Earlier crashes and unsuccessful harness-development attempts remain retained.

**Three complete packaged GUI workflows passed, with 18 normal application exits.** Each used fresh private settings and generated destinations, checking seven separate WHIP/SRT/RTMP/RTSP-TCP/RTSP-UDP/UDP/RIST profiles through switching and relaunch. URLs, credentials, stream IDs and numeric settings restored correctly; editing SRT preserved the other profiles. Deleting only the workflow's own saved Keychain item produced an error and preserved its reference through unrelated edits and cancelled Reset. Explicit Reset recovered, a new profile survived relaunch, cancelled Reset preserved it, confirmed Reset removed it, and defaults persisted. Each workflow cleaned up its two owned items. No profile data leaked into settings or application logs according to the retained fixture checks.

These are configuration/recovery workflows: capture and network output stayed off. They do not establish delivery through all seven protocols, locked-Keychain behavior or denied access. The final harness uses native accessibility actions, waits for dialog completion, and performs no selection retries.
